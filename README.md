# Cadence — English Speaking Lab

🔗 **바로 열기: https://9yogod.github.io/cadence/** (설치·서버 실행 없이 링크만 열면 돼요)

원래 단일 HTML 파일이던 프로토타입을 멀티파일(ES 모듈) 구조로 재정리한 버전입니다.

## 📱 휴대폰에서 쓰기

폰 브라우저로 위 링크를 열면 바로 쓸 수 있고, **홈 화면에 추가하면 앱처럼** 전체화면으로
열리고 오프라인에서도 동작해요 (PWA).

- **아이폰 (Safari)** — 링크 열기 → 하단 **공유 버튼(⬆️)** → **"홈 화면에 추가"**
- **안드로이드 (Chrome)** — 링크 열기 → 우측 상단 **⋮** → **"앱 설치"** 또는 **"홈 화면에 추가"**

> ⚠️ **카카오톡·네이버 등 앱 안에서 링크를 바로 누르면 설치가 안 돼요.**
> 인앱 브라우저는 '홈 화면에 추가' 메뉴 자체가 없고, **마이크(음성인식)도 막혀 있는 경우가 많아요.**
> 이 경우 앱이 알아서 감지해서 상단에 **"브라우저에서 열면 더 잘 돼요"** 안내를 띄워줍니다 —
> 거기서 Safari / Chrome으로 옮겨서 열면 돼요. (홈 화면의 **더 해보기 › 앱 설치**에서도 언제든 볼 수 있어요.)

홈 화면 아이콘으로 열면 주소창 없이 전체화면으로 뜨고, 비행기 모드/지하철에서도 화면과
연습 데이터(쉐도잉·받아쓰기·시나리오·사전)가 그대로 열려요. 기록도 폰 브라우저에 저장돼요.

> 참고: 저장된 표현·이력은 **기기별로 따로** 저장돼요 (서버가 없으니 PC ↔ 폰 동기화는 안 돼요).
> AI 실시간 대화를 폰에서도 쓰려면 Gemini 키를 폰에서 한 번 더 입력해 주세요.
> 마이크(음성인식)와 음성 재생은 **https 링크에서만** 동작해요 — 위 GitHub Pages 링크는 https라 괜찮아요.

## 실행 방법

### 가장 간편한 방법: 웹에서 바로 열기

위 링크(https://9yogod.github.io/cadence/)를 열면 끝이에요. 대화 기능(AI 실시간)을 쓰려면
홈 화면에서 본인 Gemini 무료 API 키를 한 번 입력하면 되고, 키는 각자 브라우저에만
저장돼요(서버로 전송되지 않음).

### 로컬에서 직접 실행하고 싶다면: `run.bat` 더블클릭

이 폴더의 **`run.bat`을 더블클릭**하면 서버가 백그라운드(최소화 창)로 켜지고
브라우저가 자동으로 열려요. 다 쓰고 나면 작업표시줄에 최소화된 **"Cadence server"** 창을
닫아서 서버를 끄면 됩니다. (컴퓨터에 Python이 설치되어 있어야 해요 — 대부분의 최신
Windows에는 이미 있어요.)

### 수동으로 실행하고 싶다면

`index.html`을 더블클릭해서 `file://`로 바로 열면 **크롬/엣지에서는 동작하지 않습니다**
(ES 모듈이 로컬 파일 시스템에서의 모듈 로딩을 CORS로 차단하기 때문). 아래처럼 아주 가벼운
정적 서버로 열어주세요:

```bash
# 이 폴더(cadence)에서 실행
python -m http.server 8000
# 그 다음 브라우저에서 http://localhost:8000 접속
```

또는:

```bash
npx serve .
```

또는 VS Code의 **Live Server** 확장을 쓰고 있다면 `index.html`에서 바로 "Open with Live Server".

## 지난 리팩터링에서 바뀐 점

- 1263줄 단일 HTML → 위 구조로 분리 (로직은 그대로, 순수 리팩터링)
- 음성 인식(STT) 3곳(채팅 마이크, 시나리오 마이크, 발음 체크)을 `speech.js`의

  화면에 표시되고, 에러(권한 거부/무음/네트워크)도 한국어 메시지로 통일해서 보여줍니다.

## 이번 업데이트에서 추가된 것

**1. 대화가 더 실시간처럼 느껴져요**
AI 채팅 답변을 Gemini의 스트리밍 API로 받아서, 완성된 문장이 나올 때마다 바로바로
말하기 시작해요 (전체 답변을 다 받을 때까지 안 기다려도 됨). 마이크로 말하고 나면
자동으로 전송되고요. "더 자연스러운 표현" 교정은 대화 흐름을 막지 않도록 백그라운드에서
따로 받아와요.

**2. iOS 등에서도 음성인식이 돼요**
Web Speech API가 없는 브라우저(iOS Safari 등)에서는 마이크 버튼이 사라지는 대신, 오픈소스
Whisper 모델(`Xenova/whisper-tiny.en`, Apache-2.0)을 브라우저 안에서 직접 돌려요 — 서버도
API 키도 필요 없어요. 최초 1회만 모델(약 40~75MB)을 받고, 그 다음부턴 브라우저에 캐시돼서
오프라인으로도 동작해요. 다만 이 경로는 실시간 부분 인식 대신 "녹음 → 멈추면 한 번에 인식"
방식이에요.

**3. 예문이 훨씬 다양해졌어요**
[Tatoeba.org](https://tatoeba.org)(무료 오픈 다국어 예문 데이터베이스, CC BY 2.0 FR)에서
받아온 영어-한국어 예문 약 360개를 받아쓰기·표현 복습 예문 풀에 추가했어요.

**4. 학습 진척을 볼 수 있어요**
🕘 이력에 **진척** 탭이 새로 생겨서, 받아쓰기·발음체크 정확도 추이를 그래프로 볼 수 있어요.
홈 화면의 **내 레벨 확인하기**로 간단한 진단 테스트를 받아 난이도를 바로 맞출 수도 있고,
며칠 안 하면 스트릭이 끊기기 전에 살짝 알려드려요.

## 모바일 대응 업데이트

**폰에서 앱처럼 설치돼요 (PWA)**
`manifest.webmanifest` + `sw.js`(서비스 워커) + 홈 화면 아이콘을 추가해서, 아이폰·안드로이드
모두 홈 화면에 추가하면 주소창 없는 전체화면으로 열리고 오프라인에서도 동작해요.
앱 껍데기는 미리 캐시하고, 나머지 모듈은 한 번 열어본 뒤부터 캐시돼요(다음 실행 때 최신본으로 갱신).

**터치에 맞게 손봤어요**
탭 지연(300ms)과 회색 하이라이트 제거, 작은 글씨 버튼들의 터치 영역 확대,
좁은 화면(≤420px / ≤340px)용 여백·글자 크기 조정, 가로 모드 대응,
바텀시트가 화면 밖으로 밀리지 않도록 최대 높이 + 스크롤 처리,
단어 뜻 보기 버튼이 화면 위쪽에서 잘리던 문제 수정(선택 영역 아래로 뒤집힘).

**폰에서 소리와 마이크가 제대로 동작해요**
iOS는 첫 재생이 사용자 터치 안에서 일어나지 않으면 음성 재생을 막아버려서, 첫 터치 때
무음으로 엔진을 깨우도록 했어요. Whisper 음성인식 경로도 iOS가 오디오 컨텍스트를 멈춘 채로
넘겨주는 문제를 resume 처리해서 무음 녹음이 되지 않게 고쳤어요.

**앱 안에 설치 안내를 넣었어요**
PWA로 만들어도 페이지에는 아무 표시가 안 나서, 홈 화면 상단에 설치 안내 카드와
**더 해보기 › 앱 설치** 버튼을 추가했어요. 카카오톡·네이버 인앱 브라우저는 자동으로 감지해서
"브라우저에서 열면 더 잘 돼요"(마이크가 막히는 문제 포함)로 안내하고, 카톡/안드로이드에서는
한 번에 외부 브라우저로 넘어가는 버튼을 제공해요. 이미 설치된 상태(standalone)면 안 보여요.

**서비스 워커를 network-first로 바꿨어요**
처음엔 stale-while-revalidate였는데, 그러면 배포한 내용이 **다음 실행 때**에나 보여요.
코드(js/css)는 network-first + 오프라인 시 캐시 폴백으로 바꿔서, 온라인이면 항상 최신 버전이
바로 반영되게 했어요. 아이콘·manifest만 cache-first로 남겼습니다.

## 🐞 모바일에서 앱이 안 뜨던 버그 (해결)

**증상**: 안드로이드 폰, 특히 카카오톡·네이버 인앱 브라우저로 열면 헤더만 나오고
본문이 통째로 비어 있었음.

**원인**: `renderStart()`의 첫 줄이 `speechSynthesis.cancel()`이었는데,
**안드로이드 WebView에는 `speechSynthesis`가 아예 없다.** (인앱 브라우저는 전부 WebView —
UA에 `wv`가 박혀 있음.) 그래서 홈 화면을 그리기도 전에
`ReferenceError: speechSynthesis is not defined`로 죽고 `#app`이 빈 채로 남았다.
화면 전환마다 재생을 멈추려고 부르는 호출이라 총 10군데가 같은 지뢰였다
(받아쓰기·이력·노트·세션·쉐도잉·리뷰).

**해결**: `speech.js`에 `cancelSpeech()` / `ttsSupported()`를 만들고 10곳을 전부 교체.
`typeof speechSynthesis`로 확인하므로 전역이 없든 undefined든 안전하다.
WebView를 재현해(speechSynthesis 삭제) 홈·받아쓰기·레벨테스트·노트·이력 및
세션 4단계 전부 정상 렌더링되는 것을 확인했다.

> 참고: WebView에는 음성 재생이 없으므로 **인앱 브라우저에서는 듣기 기능을 쓸 수 없다.**
> 앱이 이걸 감지해서 상단 안내 카드에 명시하고 외부 브라우저로 열도록 유도한다.

## 간격 반복(SRS) 도입

**전에는**: 복습 단계가 `seen`(마지막으로 보여준 시각) 기준으로 "오래 안 본 것 먼저"만 했다.
그건 표시 순서지 일정이 아니라서, 오늘 틀린 표현이 내일 나올지 3주 뒤에 나올지 운에 맡겨졌다.
기록은 쌓이는데 그 기록이 연습을 이끌지 못했다.

**지금은**: `js/srs.js`가 SM-2를 축약해 카드마다 다음 등장일을 계산한다.

- 복습 카드마다 **다시 / 애매 / 알아요** 3개 버튼. (6단계 대신 3단계인 이유는
  `알아요`가 `ease`로 복리 증가하면 사실상 충분하고, 33분 루틴에서 선택지는 마찰이기 때문)
- `알아요` 반복 시 간격: **1 → 3 → 8 → 20 → 50일** (상한 365일)
- `다시`를 누르면 10분 뒤 같은 세션 안에서 되돌아오고 `ease`가 0.2 깎인다 (하한 1.3)
- 복습 단계는 **마감된 카드를 오래된 순으로 먼저** 뽑고, 모자라면 임박한 것으로 채운다
- 홈 화면에 **오늘 복습할 표현 N개** 배지, 표현노트에는 카드별 다음 등장일 표시

스케줄 필드(`due/ivl/ease/reps/lapses`)는 노트 객체에 같이 들어가므로 별도 저장소가 없다.
예전에 저장한 노트는 부팅 시 `ensureAll()`이 "새 카드 = 오늘 복습 대상"으로 채워 넣는다.

채점해야 일정이 잡힌다 — 그냥 보여준 것만으로는 미뤄지지 않는다(안 한 복습은 계속 마감 상태).

## 5분 복습 모드

33분 세션은 매일 하기 어렵고, 하루 빠지면 스트릭이 끊기고, 끊기면 안 열게 된다.
그런데 간격 반복은 매일 조금씩 닿을 때 값을 하는데, 덱이 33분 세션 안에만 갇혀 있었다.

홈 화면의 **⚡ 5분 복습 · N개**로 덱만 따로 돌 수 있다 (`js/ui/quick.js`).

- 드릴 방향은 **한국어 → 영어**다. 세션 안의 복습 단계는 영어와 뜻을 같이 보여줘서
  재인(recognition)을 훈련하지만, 여기서는 뜻만 보여주고 **입으로 영어를 만든 뒤** 확인한다.
  산출(production)이 더 어렵고 더 전이되는 방향이고, 말하기 앱이 훈련해야 할 쪽이다.
- 한 번에 최대 15장 (약 5분). `다시`를 누른 카드는 10분을 기다리지 않고 **큐 뒤로 재투입**된다
  (카드당 최대 2회 — 계속 눌러도 갇히지 않게).
- 완료하면 **스트릭이 이어진다.** 단 `누적 세션`에는 안 들어간다 — 그건 정규 세션 카운트이고,
  쉐도잉 지문 회전에도 쓰이기 때문이다.

### 같이 고친 것: 같은 날 두 번 하면 스트릭이 리셋되던 버그

`finishSession()`이 "마지막 연습이 정확히 어제였나?"만 물어서, 같은 날 두 번째 완료는
`false`가 되어 스트릭이 1로 초기화됐다. 원래도 버그였지만 5분 복습이 생기면
"복습 후 세션" 조합에서 거의 매일 터진다. `state.js`의 `markPracticeDay()`로 합치고
같은 날은 유지하도록 고쳤다 (5분 복습 2회 + 정규 세션 1회를 같은 날 돌려 검증).

## 1분 스피치

쉐도잉은 정해진 문장을 따라 말하고, 대화는 주고받는다. **혼자 길게 말하는 훈련이 없었다** —
면접·발표·스피킹 시험이 요구하는 건 그건데.

주제를 보고 60초 말하면, 받아적은 내용을 돌려주고 어색한 부분을 고쳐준다 (`js/ui/speech1.js`).

- 주제 36개 내장 (`js/data/topics.js`, 업무/일상 × 초·중·고 각 6개). 각 주제에 **힌트 3개** —
  1분 말하기의 어려움은 단어가 아니라 "두 번째로 무슨 말을 할지"라서, 구성을 잡아주는 용도다.
- 교정 결과는 **틀린 표현 이력**으로, 추천 표현은 **노트**로 들어간다.
  노트는 SRS가 일정을 잡고, 5분 복습이 그걸 드릴한다 — **오늘 더듬은 표현이 내일 다시 나온다.**
- **Gemini 키 없이도** 동작한다: 전사 + 단어 수 + WPM + 힌트 체크리스트로 자가 점검.
- **마이크가 없어도** 동작한다: `⌨ 입력으로`. 인앱 브라우저는 getUserMedia가 막혀 있다.

### 마이크가 거부될 때의 복구

마이크 버튼이 녹음 화면 전환과 녹음 시작을 동시에 하기 때문에(사용자 제스처 안에서
시작해야 브라우저가 허용한다), 권한이 거부되면 **녹음은 시작되지 않은 채 60초 타이머만
도는 상태**에 갇혔다. `onStop`은 정상 종료와 실패 양쪽에서 불리고 정상 종료만 `onFinalText`가
뒤따른다는 점을 이용해, 전사 없이 멈추면 주제 화면으로 되돌리고 입력 경로를 안내한다.

## AI 발음 평가 (Gemini가 녹음을 직접 듣는다)

**전에는**: "발음 체크"가 음성인식 결과 텍스트와 원문의 단어 일치율(LCS)을 쟀다.
인식기는 문맥으로 단어를 보정하므로 엉터리로 읽어도 100%가 나오고, 인식이 어긋나면
원어민도 깎인다. 키가 있으면 더 나빴다 — 그 가짜 "걸린 단어" 목록을 Gemini에게
"이 단어들이 불분명했다"고 **알려주고** 팁을 쓰게 했다. Gemini는 녹음을 한 번도 듣지 않은 채
존재하지 않을 수도 있는 오류를 그럴듯하게 설명하고 있었다.

**지금은** (키가 있을 때, 쉐도잉 문단 보기):

```
녹음 (ScriptProcessor) → 16kHz 모노 16bit WAV 인코딩 → base64
  → generateContent: parts = [지시문 text, inline_data {mime_type:'audio/wav'}]
  → JSON: audible / heard / score / fluency / strengths / focus / words[]
```

- **WAV로 직접 인코딩** (`js/audio-rec.js`). MediaRecorder 출력은 브라우저마다 다르지만
  (Chrome webm/opus, Safari mp4/aac) WAV는 우리가 쓰는 한 형식이다. Gemini는 입력을
  16kbps 모노로 다운샘플하므로 16kHz 모노로 보내도 잃는 게 없다. 초당 32KB라 60초 상한도
  20MB 요청 한도에 한참 못 미친다. (공식 문서: audio/wav 지원, inline 20MB, 초당 32토큰)
- **지어낸 피드백 방지 장치 두 개**:
  `heard` — 비평 전에 "실제로 들은 내용"을 먼저 받아적게 해서 오디오에 근거하게 하고,
  사용자에게도 보여줘 AI가 정말 들었는지 확인할 수 있게 한다.
  `audible` — 무음·알아들을 수 없음·다른 말일 때 평가를 지어내지 않고 "못 알아들었다"고
  말할 공식 통로.
  **"한국인이 흔히 틀리는 발음(r/l, th…)" 목록은 일부러 넣지 않았다** — 이름을 대면
  실제로 틀리지 않았어도 그걸 보고하도록 유도된다.
- **temperature 0.2** — 같은 녹음에 매번 다른 점수가 나오면 평가가 아니다. 점수는 추세 차트로 간다.
- **무음은 로컬에서 거부** — 피크 0.02 미만이면 요청을 보내지 않는다(비용 + 지어내기 방지).
- 점수는 새 타입 `pron-ai`로 기록. 키 없는 단어 일치율은 `reading`으로 옮기고,
  과거의 `pronunciation` 기록은 원래 측정한 대로 "읽기 일치도"로 라벨링했다.

**키가 없을 때**: 기존 단어 대조는 유지하되 **"읽기 일치도 체크"로 이름을 바로잡고**
"이건 발음 평가가 아니에요 — 인식기는 문맥으로 단어를 보정하거든요"라고 명시한다.

### 만들면서 잡은 것

- **녹음 시작 직후 첫 단어 잘림**: getUserMedia가 반환된 뒤 첫 오디오 버퍼가 들어오기까지
  공백이 있어서, "녹음 중"을 보고 읽기 시작하면 앞부분이 빠졌다(2.0초 녹음 → 1.19초 오디오).
  첫 버퍼가 도착한 뒤에만 녹음 중으로 표시하도록 바꿔 3회 연속 2.0초 → 2.05초.
- **녹음 버튼 무한 대기**: `AudioContext.resume()`/`close()` 프로미스는 끝나지 않을 수 있다.
  둘 다 짧은 타임아웃과 경쟁시켜 어떤 경우에도 진행되게 했다.

### 한계 (정직하게)

압축된 녹음을 LLM이 듣고 판단하는 것이라 **음소 단위 전용 발음 분석기만큼 정밀하지 않다.**
화면에 이 점과 "AI가 들은 내용"을 함께 보여줘, 들은 내용이 실제와 크게 다르면 점수를
참고만 하도록 안내한다. 실제 Gemini 응답 품질은 키로 직접 써봐야 판단할 수 있다
(개발 중 검증은 요청 형식·오디오 인코딩·응답 처리까지이며, 실제 모델 판정은 포함하지 않는다).

## 무료 한도에 맞춰 요청 줄이기

무료 키는 **모델당 하루 20회**다 (429 응답의 quotaValue로 확인, 프로젝트·모델 단위).
그런데 AI 대화는 사용자가 한 마디 할 때마다 Gemini를 **두 번** 불렀다 — 답변 생성 1회,
즉시 교정 1회. 10마디 대화면 22회로 **정규 세션 한 번에 하루치가 끝났다.**

- **즉시 교정을 선택식으로 바꾸고 기본을 껐다.** 리뷰 단계가 이미 대화 전체를 분석해
  교정을 보여주므로 기능이 없어지는 게 아니라 "지금 즉시"가 빠질 뿐이다.
  대화 화면의 토글로 켤 수 있고, 켜면 요청이 2배라고 문구에 적어뒀다.
- **오늘 쓴 횟수를 앱에서 보여준다** (Gemini 키 설정창). 앱이 보낸 호출을 세는 방식이라
  다른 기기·앱에서 쓴 건 모르지만, "앱이 고장났나"와 "오늘 18회 썼구나"는 다르다.

측정 결과 (한 턴 기준): **2회 → 1회**. 10마디 세션 기준 24회 → 14회.

세션 시작만으로도 3회가 나간다 (복습 단계 예문 생성 1, 쉐도잉 AI 지문 생성 1, 대화 첫 인사 1).
